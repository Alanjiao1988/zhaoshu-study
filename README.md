# 少年主公 · 学习军令台

把孩子的学习任务翻译成「治国安邦」：点卯得军功，军功招名将，名将录图鉴。
主要给孩子在 **iPad** 上用（竖屏单栏、横屏「军令 | 战况」两栏），手机和电脑也能打开。纯前端、零依赖、数据存在浏览器 localStorage 里。可以直接双击 `index.html` 打开，也可以挂到任意静态服务器上（这样还能离线用、能「添加到主屏幕」）。

```bash
npm start        # python3 -m http.server 8080，然后打开 http://localhost:8080
npm test         # 规则层单元测试（Node 22，无需安装依赖）
npm run check    # 所有脚本语法检查
```

## 在 iPad 上安装

1. 在 iPad 的 Safari 里打开 **https://alanjiao1988.github.io/zhaoshu-study/**
   （代码推到 `main` 后，GitHub Actions 会先跑测试、再自动发布到这个地址，见 `.github/workflows/pages.yml`）。
2. 点「分享 → 添加到主屏幕」，之后就像 App 一样全屏打开，没网也能用。
3. 不要用「文件」App 直接打开 `index.html`：iPad 会禁用本地存储，记录关掉就丢（页面顶部会有红色提醒）。
4. 数据只存在这台 iPad 的 Safari 里，定期在「设置 → 导出备份」存一份。

## 目录结构

| 文件 | 职责 |
|---|---|
| `index.html` | 页面骨架：顶栏、主区、底部导航，按顺序加载脚本 |
| `css/style.css` | 全部样式（沿用原版宣纸 · 朱砂 · 墨配色与节日皮肤）；末尾是 iPad 布局和触屏覆盖 |
| `js/config.js` | 静态数据：版本号、科目、劲敌、官职、徽章、36 名将、书目 |
| `js/util.js` | 日期 / 转义 / 加权随机等纯函数；`NOW` 可在测试里替换 |
| `js/store.js` | 默认状态、`migrate()` 版本升级、localStorage 读写 |
| `js/rules.js` | 核心规则：应做清单、补录窗口、账本冻结、连击、军功、招贤令 |
| `js/features.js` | 玩法：兑现台、难度建议、抽卡与保底、毕业、成就、一周汇总 |
| `js/ui.js` | 弹窗、提示、彩带、顶栏、视图切换 |
| `js/views/*.js` | 六个页面：今日、一周、武将、点将台、军报、设置 |
| `js/main.js` | 启动、每日仪式卡、毕业典礼、跨午夜自动刷新 |
| `sw.js` / `manifest.webmanifest` | 离线缓存（页面网络优先、其余缓存优先）与 PWA 安装信息 |
| `tests/` | 规则层测试（`vm` 加载）+ 发版检查（版本号、预缓存清单） |

分层原则：`config → util → store → rules → features` 不碰 DOM，可在 Node 里测试；界面层只负责拼 HTML 和调用上面的函数。
仍然使用经典 `<script>` 而不是 ES module，因为 `file://` 下 module 会被浏览器拦掉。

## 核心规则

- **补录窗口**：最近 3 天（含今天）可以补点卯；更早的日子会结算进账本（`ST.ledger`）并冻结。之后改任务、删任务、加休整期都改不动历史上的军功和招贤令。
- **军功** = 冻结账本 + 窗口内实时计算 + 重复名将折算。官职按历史最高军功授予，只升不降。
- **连击**：连续军令齐备的天数，3/5/7 天分别 ×1.2/×1.5/×2；休整日跳过，不算断。
- **招贤令**：一天军令齐备得 1 枚，破当日劲敌再得 2 枚。揭榜 78% 出武将、22% 出锦囊，连揭 20 次没出神将必出一次。
- **兑现台**：开锦囊时发一张兑现券，家长点「已兑现」才算结账，并统计兑现率。
- **主动性**：孩子自己加任务、说「太难」、休整期主动开工、标记心愿，都会记进军报。

## 这次重构修掉的问题

相对于原来的单文件 v1.5.1：

1. **老数据升级从没执行过**：`load()` 把存档合并到自带最新 `schema` 的默认状态上，导致没有 `schema` 字段的老数据被当成已是最新版，v1→v3 的升级规则一条都没跑。现在 schema 取自原数据。
2. **连击早上显示为 0**：今天还没做完时，连击从今天往前数，一开始就断了。现在今天未完成时从昨天往前数。
3. **「补发招贤令」在没揭过榜时无效**：原来靠把 `draws` 往回减，`draws` 为 0 时补不出来。改为单独的 `bonusTickets` 字段（数据结构 v4）。
4. **锦囊互换判断反了**：原来只有门槛「各不相同」时才放行。现在只有同一门槛下至少两件时才能换。
5. **导入备份不走升级流程**：现在导入和读档走同一个 `hydrate()`，导入后会立刻结算账本。
6. **回看前几天时，「出战」按钮打的却是今天的劲敌**：现在只有今天能出战；也不能提前给未来的日子点卯。
7. **删除休整期会解冻并重算历史账页**，违背了冻结原则。现在冻结日的休整状态以账本为准，休整期最早只能从补录窗口开始。
8. **事后加的休整期会收回当天已得的招贤令**：当天已经点过卯的日子不再算休整日。
9. **毕业判定没跳过休整日**，生病一周就毕不了业。现在毕业和难度建议共用同一个按周统计函数，休整日不计入。
10. 「完美一周」徽章在周一做完一天就会发，现在只认已经过完的整周。
11. 删除军令时连冻结日的点卯记录也一起删掉（那是账本的原始凭证），现在只删窗口内的。另外新增「暂停」，可以只停不删。
12. 点卯后页面会跳回顶部，现在只在切换页面时回顶。点将台的官职进度改用历史最高军功，和顶栏一致。「还差 x 军功」不再出现 109.19999 这类浮点误差。
13. 应用开着跨过午夜时，会自动结算并切到新的一天。

## 数据结构版本

| schema | 变化 |
|---|---|
| 1 | 初版（无 schema 字段） |
| 2 | 兑现台、休整期、自愿开工、主动性记录 |
| 3 | 补录窗口：窗口内的账页放开重算 |
| 4 | `bonusTickets` 单独记录补发的招贤令 |

以后要加字段：`SCHEMA` +1，在 `migrate()` 里补一条 `if(s.schema < N)` 的规则，再在 `tests/logic.test.js` 里加一个用例。

## 发新版本

离线缓存对 js/css 是**缓存优先**：只要版本号不变，iPad 上就一直用缓存里的旧文件。所以每次改完代码：

1. 把版本号同时改到 `js/config.js`（`APP_VERSION`）、`sw.js`（`VERSION`）、`package.json`（`version`）。
2. 新加了文件就加进 `sw.js` 的 `ASSETS`。
3. 跑 `npm test`：版本号不一致、`index.html` 引用的文件没进预缓存，都会报错。

iPad 下次联网打开时会装上新版本、清掉旧缓存；有时要关掉再开一次才生效。
